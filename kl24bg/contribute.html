This is a project anyone can contribute to. Yes, you.

Open source didn’t win because a company built it — it won because everyone did. The corpus grows the same way: incremental and permissionless. If you know git, you already know the workflow.

four ways in

Data, code, hosting, curation — every one of them moves the project.

contribute data

Grow the corpus

The heart of the project. Gather or generate openly licensed data — or write a fetcher for a public source — run one ingest, and open a DCO-signed pull request. Your commit is the contribution, and every model trained afterward carries it in its bill of materials.

contribute code

Build the toolchain

The waldo CLI is one Go binary: converters, fetchers, training backends (MLX, PyTorch, torchtitan), verification, stores. Ordinary open source development — issues, PRs, reviews — in the toolchain repo.

contribute hosting

Host & mirror the bytes

Shard bytes live in federated, contributor-hosted storage — any S3 bucket or static HTTPS host. Hosting a corpus or running a mirror makes the commons faster and more durable, and content addressing means your copy is verifiably identical.

contribute judgment

Curate & review

Review data PRs, check license claims, verify sources, improve the docs. The license bar is enforced by humans with taste and rigor — the same peer review that keeps every serious open source project honest.

the contribution flow

One ingest, one sign-off, one pull request.

Contributions happen inside a checkout of the index repo, git-style. The -s is your DCO attestation — made with your own git identity — that the data is redistributable under the license you declared. The diff plus the URLs in it are the entire contribution.

your first data contribution
# 0. install waldo, fork + clone the index
$ git clone https://github.com/openwaldo/waldo-index.git && cd waldo-index

# 1. get raw data — gathered yourself, or via a fetcher (worked examples)
$ go run ../waldo/fetchers/fetch-gutenberg -ids 1342,84,1661 -out /tmp/raw
wrote /tmp/raw/fetch-log.json (per-file provenance for ingest)

# 2. ingest: convert deterministically, pack, push shards, write the manifest
$ waldo index ingest /tmp/raw core/books --name gutenberg-set --license CC0-1.0
ingested 3 docs into 1 shard(s): 1 uploaded — tree verified ok

# 3. sign it, push it, open the PR
$ git add core index.json && git commit -s -m "Add gutenberg-set"
$ git push  # → open the pull request; CI re-verifies the whole tree

what the corpus needs most

The clean pool has gaps. Filling one is a named, lasting contribution.

1

Math & structured reasoning

The biggest gap: the standard math sets fail the license bar. Clean paths exist — synthetic generation with clean-generator models, public-domain texts, CC-licensed Q&A.

2

Instruction & preference data

Community-collected conversation data is the only unbounded clean source — the OASST model proved it works. Human turns, openly licensed.

3

Multilingual breadth

The public-domain and CC pool outside English and French is barely tapped: national libraries, government works, Wikipedia editions.

4

Fresh, permissive code

Permissively licensed repositories ingested directly with per-file SPDX fidelity — freshening a corpus that ages fast.

5

Newly opened archives

Every institution that flips a collection to genuinely open terms is one fetch-and-ingest away from the index. Help us find them.

+

Compute & funding

The growth ladder is funding-honest: laptops prove the pipeline, rented nodes build the first useful models, and the foundation rung needs partners. Donated cluster time moves the whole project up a stage.
