Ways to contribute

The whole project
needs contributors.

CONTRIBUTION IS NOT A HARDWARE CLASSUseful work starts with attention, judgment, and a willingness to learn.

Some contributors write Go or operate GPUs. Others test instructions, explain a hard concept, review evidence, report a failure, or help someone else get started.

  1. 01

    Community + learning

    Learn AI infrastructure in public, ask good questions, share experiments, review proposals, and help other people participate.

  2. 02

    Tooling + infrastructure

    Improve the CLI, ingestion adapters, training backends, tests, packaging, integrations, reliability, and operator experience.

  3. 03

    Data + provenance

    Prepare source material, review evidence and asserted licenses, audit corpus records, propose corrections, and publish accountable contributions.

  4. 04

    Models + evaluation

    Develop composes, reproduce training runs, evaluate behavior, compare backends, report results, and improve model workflows.

  5. 05

    Compute + documentation

    Run bounded experiments on available hardware, document what worked, create tutorials, and coordinate larger efforts with the community.

Learning the system is a valid way to begin contributing.

Follow a real workflow, record what was confusing, and turn that experience into a fix, issue, test, example, or explanation that helps the next contributor.

Accountability at scale

Sign the contribution.
Stand behind the claim.

The Developer Certificate of Origin (DCO) is a lightweight accountability mechanism proven across open-source software. A sign-off connects each submitted change to a contributor who certifies that they created it—or otherwise have the right to submit it under the project’s license—and understands that the contribution is public.

Read the DCO ↗
01 / IDENTIFY

Identify the contributor.

git commit -s adds a Signed-off-by trailer using the contributor’s Git identity.

02 / ATTEST

Make responsibility explicit.

The sign-off records the contributor’s certification instead of leaving provenance as an anonymous upload or an implied promise.

03 / PRESERVE

Keep the record public.

The commit, sign-off, review, automated checks, corrections, and history remain together in the public project record.

Accountability is evidence—not magic.

A DCO sign-off does not prove that every technical or legal claim is correct. It makes the contribution attributable, explicit, reviewable, and challengeable.
