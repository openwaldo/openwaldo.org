howto · waldo build

Build and train a model, directly.

What this HOWTO does: builds a model with CLI commands alone — size an architecture against the corpus, init it, train it on an index path, and ship weights that carry their own bill of materials. The shortest path from corpus to model, and what the compose document is shorthand for.

Set expectations honestly: every model here is a base model — it continues text the way a book does. It does not answer questions and does not converse (waldo chat says so on startup). And a small model trained on a slice of the corpus generates English-shaped babble; that’s the correct result at that scale. What you’re really building is the discipline: a model that carries its own bill of materials.

step 0

What you need

The waldo binary, a checkout of the index with at least one corpus, and uv — the training harness runs through it and resolves its own dependencies, so there’s no Python environment to set up.

Backends are chosen by the machine, never declared: MLX on Apple Silicon, PyTorch everywhere else (CUDA, ROCm, MPS, or CPU at runtime). Weights are byte-compatible between them, so you can prototype on a laptop and continue the same model on a GPU node.

macOS — install
# prerequisites: git, Go 1.24+, and uv
$ brew install go uv

# build and install the waldo binary, then clone the public index
$ git clone https://github.com/openwaldo/waldo.git && cd waldo && make install
$ git clone https://github.com/openwaldo/waldo-index.git && cd waldo-index

# training backend: MLX, auto-detected on Apple Silicon — nothing to configure
Linux — install
# prerequisites: git, Go 1.24+, uv, and the NVIDIA driver for GPU training
$ sudo dnf install golang git   # or apt install golang-go git
$ curl -LsSf https://astral.sh/uv/install.sh | sh

# build and install the waldo binary, then clone the public index
$ git clone https://github.com/openwaldo/waldo.git && cd waldo && make install
$ git clone https://github.com/openwaldo/waldo-index.git && cd waldo-index

# training backend: PyTorch, auto-detected on CUDA — add --gpus N for multi-GPU
step 1

Size the model against the corpus

Tokens-per-parameter math, done for you — which model size this much data can actually support.

recommend
$ waldo model recommend core/books
rung   params    tokens/param at 1 epoch
  10m  9.5M      0.0534
→ 10m
recommended: 10m — the largest rung this corpus feeds to at least compute-optimal
step 2

Create, then train

Architecture is immutable after init. Training a subtree path trains every manifest beneath it, and each run records a BOM: the index commit, every consumed manifest’s hash, data totals, and the builder version. Re-running is make-style — a completed stage with unchanged data, recipe and hyperparameters is skipped. Models live in ~/.waldo/models/ — machine artifacts, never repo content.

Note the warnings below: six books is 510K tokens, so even the smallest rung is starved. They’re correct and worth heeding.

init & train
$ waldo model init bookworm --preset 10m --context 512
created bookworm: 6 layers, 384 hidden, 6 heads (2 kv), ffn 1024, context 512,
  vocab 259 (byte) — ~9.5M params

$ waldo model train bookworm core/books --steps 200
warning: pretrain corpus is ~510.0K tokens against ~9.5M params (0.0534 tokens/param
  at 1 epoch) — severely data-starved; consider a smaller rung or more data
=== pretrain (1/1): core/books (200 steps, backend mlx) ===
step   200  loss 1.7871  (avg10 1.8345)
done: final loss 1.7871 (held-out 1.8345)
trained: bookworm — BOM-pinned; try `waldo chat bookworm`
step 3

Measure it, then ship it

PROVENANCE.md is why any of this exists, and the BOM chain is embedded inside the safetensors too, so the weights carry their own history even when separated from the directory. The replay guarantee is exact for the inputs: anyone with your index commit rebuilds from the same data, recipe and architecture. Weights themselves are not bit-deterministic across GPUs, and the tool does not pretend otherwise.

test, inspect, chat, export
$ waldo model test bookworm core/books
eval: loss 1.7947, perplexity 6.02 over 2188772 tokens

$ waldo model info bookworm            # runs, BOMs, lineage, saturation
$ waldo chat bookworm                  # it continues text; it does not answer
$ waldo model export bookworm ~/out
exported bookworm → ~/out
  model.safetensors (~9.5M params)
  model.json
  PROVENANCE.md (3 lineage events, 2 runs)

Where to go next

That is the whole direct path. It works, and it does not scale to a curriculum you want to keep, share, or re-run six months later. For that, declare the build in one reviewable file: WALDO compose. Or skip waldo as a trainer entirely and take the data to your own stack: WALDO export.
