03 / CONTRIBUTE

WALDO turns acquired source material into canonical, audited shards and a small Git review overlay. The bytes stay out of Git. The meaning stays in public review.

Ingest your first corpus ↗

One ingestion path

Bring files.
Or bring a recipe.

Direct input and reviewed external acquisition both enter the same probe, conversion, audit, publication, purge, and contribution pipeline.

DIRECT INPUT

You already have the files.

Point WALDO at text, Markdown, plain or compressed JSONL, or raw Parquet. A dry run probes the inputs and prints the conversion plan without writing or uploading.

waldo index ingest ./acquired-data ./waldo-index/core/example
REVIEWED RECIPE

The source must be acquired.

A strict recipe calls reviewed external fetcher scripts into a WALDO-owned temporary directory. The fetcher cannot mutate the index, publish objects, or train a model.

waldo index ingest ../waldo-fetchers/recipes/example.yaml …

What WALDO does next

Make the contribution
small enough to review.

  1. 01

    Sense

    Detect the input from its content and schema—not its filename alone.

  2. 02

    Convert

    Stream into tokenizer-neutral canonical Parquet with recorded conversion identity.

  3. 03

    Audit

    Reopen each shard and validate schema, records, hashes, and exact totals.

  4. 04

    Publish

    Upload content-addressed objects to lookaside storage and verify the remote bytes.

  5. 05

    Review

    Produce a compact Git overlay for normal DCO, diff, and repository review.

WALDO does not silently commit or open a pull request.

It prepares deterministic evidence so normal project governance remains visible.

LOOKASIDE / CONTENT-ADDRESSED

Canonical bytes

  • Self-contained Parquet
  • SHA-256 object identity
  • No loose media
  • No hidden catalogs
  • No metadata sidecars
