the machinery

Models built the way open source builds software — from source.

The training data is the model’s source code — so OpenWALDO manages it like code: proposed, reviewed, licensed, recorded, and removable in the open, with every model carrying a verifiable bill of materials pointing back at exactly the data that made it.

the design

Curation lives in git. Bytes live in federated object storage. Content hashes join them.

the index

Managed, curated, ordered

A git repository of metadata: for every shard of every corpus, what it is (sha256), where it came from (sources, licenses), how it was derived (recipe), and where it lives (a URL). Contribution is an ordinary pull request with a DCO sign-off.

the lookaside cache

Federated, content-addressed blobs

The actual training bytes — hosted by contributors themselves on any S3 bucket or static HTTPS host, never by the project. Reads are anonymous; every fetched byte verifies against its manifest sha256. No host can serve the wrong data undetected.

the waldo CLI

One Go binary, the whole lifecycle

Walking and verifying the index, pushing to and fetching from lookaside stores, deterministic ingestion, and model init / train / fork / chat / export with full lineage.

raw data

Fetch or gather

Any local corpus of data — gathered, curated, or generated by you, with per-file provenance.

→
index + lookaside

Ingest

Convert → dedup → pack → push shards to a lookaside, write the manifest and index entries. Deterministic: same input, same hashes, every time.

→
models

Train & ship

Init or pull a model, train on index paths, fork, test, chat — and export with its bill of materials.

using it

Git-style, end to end.

You stand in a checkout of the index and the waldo CLI does everything. Consuming the corpus needs no account and no credentials — reads are anonymous and hash-verified. Every output below is real. (Contributing data back is one ingest and a pull request — see community.)

clone → verify → train → export
# 1. install the toolchain (one binary), clone the public index —
#    that's the entire setup
$ git clone https://github.com/openwaldo/waldo.git && cd waldo && make install
$ git clone https://github.com/openwaldo/waldo-index.git && cd waldo-index

# 2. trust nothing — check everything: every committed shard, against its hash
$ waldo index verify
checked: 14 index(es), 7 manifest(s); declared 40 shard(s), 497713 docs, 2.8B tokens
bytes:   40 object(s) confirmed present in the store (existence + size; --fetch re-hashes)
ok

# 3. see what the corpus holds — tokens, licenses, and the training math
$ waldo index summary
.: 7 corpus(es), 40 shard(s)
  tokens  2.8B (reference-tokenizer estimate)
by license:
  CC-BY-4.0                18 shard(s)      2.0B tokens
  CC0-1.0                   2 shard(s)     86.8M tokens   …
  recommended rung: 90m (~75.7M params) — 37 tokens/param at 1 epoch

# 4. train on index paths — shards fetch anonymously, verify, and cache
$ waldo model init bookworm --preset 10m   # rungs 10m … 405b, or --params 42b
$ waldo model train bookworm core/books
pretrain  step    12/12 (100.0%)  loss 3.2147  (avg10 3.7903)
done: final loss 3.7903 (held-out 3.4355)
run 1 complete — BOM pinned (1 manifests, index commit 8d04e24c3fbc)

# 5. talk to it, ship it with its ancestry — or take the data to your own tools
$ waldo chat bookworm
$ waldo model export bookworm ~/bookworm-export
  model.safetensors (~9.5M params; provenance embedded in the safetensors metadata)
  model.json
  PROVENANCE.md (2 lineage events, 1 runs)
$ waldo index export science --license "CC-BY-*" ~/corpus   # plain JSONL + EXPORT.json

Deterministic by construction

Same input + same recipe → identical shard hashes. Canonical JSON, records sorted by hash, a pinned compressor compiled into the binary. Re-running an ingest is a byte-level no-op.

Identity beats location

Every artifact is named by its content hash. Mirrors, migrations, and rehosting change nothing: the bytes either match or they don’t.

Backends discovered, never assumed

MLX on Apple Silicon, PyTorch / torchtitan on CUDA — chosen at runtime, overridable by config. Weights interchange as safetensors, so the same model moves from laptop to cluster.

model.json          ← the machine-readable BOM
PROVENANCE.md       ← the human-readable ancestry

Four artifacts, one discipline: the manifest records what went in, verify proves it's still there, EXPORT.json carries the pedigree out to your tools, and the model BOM pins every trained weight back to the commit that fed it. Nothing above requires trusting the project — only checking it.

the license bar

Every byte in the official tree is one a mirror can host without inheriting a lawsuit.

The official index admits only content that is genuinely open — public domain, CC-BY, CC-BY-SA, and permissively licensed code — attested by DCO sign-off as redistributable under its stated SPDX license. The bar applies to the underlying documents, not just a dataset’s compilation license, because a permissive label on a bundle says nothing about the copyright of what’s inside it.

That’s a strict bar, and it has an honest price: the web-crawl datasets that trained most recent open models don’t clear it. The projects that proved license-clean training works — EleutherAI’s Common Pile, AI2’s OLMo, Pleias’ Common Corpus — showed the gap is corpus size and diversity, not anything fundamental. Growing that clean corpus is exactly what this project exists to do.

And openness includes the right to leave: takedown is a first-class operation, obligations like attribution travel with the manifests, and per-shard license tags mean any downstream consumer can include or exclude by SPDX id.

the growth ladder

What you can build on the corpus, at every scale.

OpenWALDO doesn’t ship models — it ships the source and the toolchain, and you set the ambition. The ladder below is what the corpus supports as it grows, from a laptop experiment to a from-scratch foundation model (with, at most, small reference examples from the project to prove the pipeline).

Stage A10–100M params
GPU laptops or mini-systems

Prove the pipeline

Books + reference corpora, trained on a laptop (Apple Silicon / MLX) or any single GPU. A tiny model whose entire existence — tokenizer, corpus, run config — replays from one index commit. Quality is explicitly not the point; the BOM chain is.

Stage B~1B params
GPU or multi-GPU servers

First useful models

A ~115B-token license-clean corpus — books, wikis, code, papers, law — through the full pipeline: pretrain, anneal, SFT, preference. One big GPU box (an 8× H100/H200 node, rented for days) puts this rung within reach of any team or serious community member.

Stage C3–7B params
GPU clusters

Foundation models

The full clean pool plus everything the community ingests along the way supports from-scratch foundation models with a provable, replayable, license-clean pedigree. This is GPU-cluster territory — AI labs, large companies, donated compute — built by whoever brings it, and auditable by everyone.

Beyond13B → 405B
AI-lab scale

The frontier trains on the commons

Stage C is the proof, not the ceiling. From there the corpus becomes what it was always meant to be: the base layer for AI labs — pulled as the substrate for frontier-scale training, or blended into existing corpora at any size. The presets run to 405B and derive a coherent shape for any target beyond, so the tooling never caps ambition. And every model that draws on the commons, at any scale, gains what no private pipeline can offer: a publicly auditable slice of its diet.

built to be built on

A foundational corpus. Add your value on top.

This is where open source shines: a shared, collaboratively maintained base that nobody has to rebuild and everybody gets to build on — the way companies build products on Linux rather than writing kernels. The corpus is the foundation; differentiation happens above it. Model providers pretrain clean bases here and layer their proprietary fine-tuning, alignment, and domain skill on top. Companies feed the corpus into stacks and models they already have. Both inherit the same audit trail — and every improvement to the commons lifts everyone's foundation at once.

model builders — your base from the commons, your value on top
# pretrain a base on the shared corpus — the whole build declared
# in one reviewable file, every stage BOM-pinned
$ waldo compose build configs/base1b.yaml

# then add what makes it yours: fork carries the lineage, and your
# proprietary SFT / domain anneal trains from a private tree — same
# toolchain, nothing published
$ waldo model fork base1b acme-assistant
$ waldo train acme-assistant private/support-dialogues
# the public BOM covers the foundation; your edge stays yours
companies — feed the models and stacks you already run
# take exactly the license profile your product allows, as plain JSONL
$ waldo index export core science --license "CC-BY-4.0,CC0-1.0" ~/clean
exporting 22 shard(s): … + EXPORT.json

# now it's yours to use anywhere: continued pretraining of an existing
# open model, a RAG index, an eval set — your tools, your stack, with
# EXPORT.json carrying the pedigree into your compliance story

And the loop closes the open-source way: what you can openly license — docs, knowledge bases, domain corpora — you contribute back, and every model built on the foundation afterward knows it. A few of the shapes this takes:

Teach every model your product

Openly license your docs, guides, and knowledge bases, ingest them with one command, and open a PR. Every model trained on the tree afterward knows your product — with provenance instead of hallucination.

Internal & domain models

The same toolchain works on a private tree: waldo index init, ingest internal data, train or fork domain models — with a BOM your compliance team can actually read. Nothing has to be published.

Auditable AI for regulated work

Finance, healthcare, government: when the auditor asks “what is this model built from?”, the answer is a signed, hash-pinned record — not a shrug. License partitioning and takedown are built into the format.

Sovereign & public AI

A model whose entire training input is inspectable, license-clean, and rebuildable inside your own borders. Where it was trained stops mattering, because what it was trained on is on the record.

Reproducible research

A published model anyone can replay: same index commit, same data, same recipe, same architecture. Ablations and dataset studies become diffs against a pinned tree instead of archaeology.

Clean-room model supply

Building a product on a model? Per-shard SPDX tags let you train from precisely the license profile your product allows — include or exclude by tag, and ship the audit trail with it.

the incentive

The corpus is the commons. The models are proof it works.

Everything you contribute is carried — by hash, by license, by name — in every model that learns from it.
