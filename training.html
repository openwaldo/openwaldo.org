the machinery

Models built the way open source builds software — from source.

The training data is the model’s source code — so OpenWALDO manages it like code: proposed, reviewed, licensed, recorded, and removable in the open, with every model carrying a verifiable bill of materials pointing back at exactly the data that made it.

the design

Curation lives in git. Bytes live in federated object storage. Content hashes join them.

the index

Managed, curated, ordered

A git repository of metadata: for every shard of every corpus, what it is (sha256), where it came from (sources, licenses), how it was derived (recipe), and where it lives (a URL). Contribution is an ordinary pull request with a DCO sign-off.

the lookaside cache

Federated, content-addressed blobs

The actual training bytes — hosted by contributors themselves on any S3 bucket or static HTTPS host, never by the project. Reads are anonymous; every fetched byte verifies against its manifest sha256. No host can serve the wrong data undetected.

the waldo CLI

One Go binary, the whole lifecycle

Walking and verifying the index, pushing to and fetching from lookaside stores, deterministic ingestion, and model init / train / fork / chat / export with full lineage.

raw data

Fetch or gather

Any local corpus of data — gathered, curated, or generated by you, with per-file provenance.

index + lookaside

Ingest

Convert → dedup → pack → push shards to a lookaside, write the manifest and index entries. Deterministic: same input, same hashes, every time.

models

Train & ship

Init or pull a model, train on index paths, fork, test, chat — and export with its bill of materials.

Deterministic by construction

Same input + same recipe → identical shard hashes. Canonical JSON, records sorted by hash, a pinned compressor compiled into the binary. Re-running an ingest is a byte-level no-op.

Identity beats location

Every artifact is named by its content hash. Mirrors, migrations, and rehosting change nothing: the bytes either match or they don’t.

Backends discovered, never assumed

MLX on Apple Silicon, PyTorch / torchtitan on CUDA — chosen at runtime, overridable by config. Weights interchange as safetensors, so the same model moves from laptop to cluster.

the receipts

Validation, auditability, and a bill of materials — as artifacts, not promises.

Every claim is checkable by anyone, anonymously, with one command — the walkthroughs show each of these artifacts being made, with real output from the live public index.

The manifest: what an auditor reads

Every corpus is a signed, human-readable record. The recipe is pinned down to the compressor version compiled into the binary — and every shard carries its own hash, license, sources, and doc, token, and byte counts. waldo index verify proves the store still matches it: existence and size for every shard by default, a full re-hash of the actual bytes on request — anonymous, no account, no keys.

The model BOM: weights that carry their source

waldo model export writes three artifacts: the weights with provenance embedded inside the safetensors metadata, a machine-readable BOM, and a human-readable PROVENANCE.md — the ancestry travels with the weights file itself, not beside it. Every run records the index commit, the consumed manifests' hashes, and the data totals. Ask "what is this model built from?" and the answer is a hash-pinned record, replayable from one git commit.

EXPORT.json: the pedigree travels with the data

Exporting any subtree writes parquet that is byte-identical to what the manifest hashes, plus EXPORT.json — the data-side BOM: the index commit and every file's hash, license, and origin. Downstream artifacts cite their source.

Nothing here requires trusting the project — only checking it.

the license bar

Every byte in the official tree is one a mirror can host without inheriting a lawsuit.

The official index admits only content that is genuinely open — public domain, CC-BY, CC-BY-SA, and permissively licensed code — attested by DCO sign-off as redistributable under its stated SPDX license. The bar applies to the underlying documents, not just a dataset’s compilation license, because a permissive label on a bundle says nothing about the copyright of what’s inside it.

That’s a strict bar, and it has an honest price: the web-crawl datasets that trained most recent open models don’t clear it. The projects that proved license-clean training works — EleutherAI’s Common Pile, AI2’s OLMo, Pleias’ Common Corpus — showed the gap is corpus size and diversity, not anything fundamental. Growing that clean corpus is exactly what this project exists to do.

And openness includes the right to leave: takedown is a first-class operation, obligations like attribution travel with the manifests, and per-shard license tags mean any downstream consumer can include or exclude by SPDX id.

knowledge by policy

Ask for knowledge the way you’d query a database.

Because every shard carries its metadata — license, source, origin, format, path — the corpus can be queried, not just downloaded. That already works for licenses today: waldo index export code --license "GPL-*,MIT,Apache-2.0" assembles a corpus from exactly the license profile you accept.

Follow that idea forward. “Build me a Linux kernel expert” isn’t really a prompt — it’s a policy: lean the mix heavily toward code; accept GPL and permissive licenses; prefer kernel and systems sources; favor recent material over stale. As the index grows richer metadata — domains, review depth, recency — that policy becomes an executable query, and the query assembles the training corpus.

The payoff is the answer to a simple question: where did this model come from? Today the industry’s honest answer is a shrug — “approximately four trillion tokens.” A model built from a corpus query answers differently:

Expert 3.2 was trained from OpenWALDO query 98a7f… — 2.4 billion licensed tokens, from 18,247 contributors, under these licenses.

The query’s receipt is the model’s bill of materials — reproducible by anyone, forever. The license dimension ships today; the rest is the roadmap, and every contribution makes the queries richer.

the growth ladder

What you can build on the corpus, at every scale.

OpenWALDO doesn’t ship models — it ships the source and the toolchain, and you set the ambition. The ladder below is what the corpus supports as it grows, from a laptop experiment to a from-scratch foundation model (with, at most, small reference examples from the project to prove the pipeline).

Stage A10–100M params
GPU laptops or mini-systems

Prove the pipeline

Books + reference corpora, trained on a laptop (Apple Silicon / MLX) or any single GPU. A tiny model whose entire existence — tokenizer, corpus, run config — replays from one index commit. Quality is explicitly not the point; the BOM chain is.

Stage B~1B params
GPU or multi-GPU servers

First useful models

A ~115B-token license-clean corpus — books, wikis, code, papers, law — through the full pipeline: pretrain, anneal, SFT, preference. One big GPU box (an 8× H100/H200 node, rented for days) puts this rung within reach of any team or serious community member.

Stage C3–7B params
GPU clusters

Foundation models

The full clean pool plus everything the community ingests along the way supports from-scratch foundation models with a provable, replayable, license-clean pedigree. This is GPU-cluster territory — AI labs, large companies, donated compute — built by whoever brings it, and auditable by everyone.

Beyond13B → 405B
AI-lab scale

The frontier trains on the commons

Stage C is the proof, not the ceiling. From there the corpus becomes what it was always meant to be: the base layer for AI labs — pulled as the substrate for frontier-scale training, or blended into existing corpora at any size. Every model that draws on the commons, at any scale, gains what no private pipeline can offer: a publicly auditable slice of its diet.

built to be built on

A foundational corpus. Add your value on top.

This is where open source shines: a shared, collaboratively maintained base that nobody has to rebuild and everybody gets to build on — the way companies build products on Linux rather than writing kernels. The corpus is the foundation; differentiation happens above it — and every improvement to the commons lifts everyone's foundation at once.

Model builders — your base from the commons, your value on top

Pretrain a base on the shared corpus — the whole build declared in one reviewable compose document, every stage BOM-pinned. Then add what makes it yours: a fork carries the lineage, and your proprietary SFT and domain anneal train from a private tree with the same toolchain, nothing published. The public BOM covers the foundation; your edge stays yours.

Companies — feed the models and stacks you already run

Export exactly the license profile your product allows, as parquet shards, and it's yours to use anywhere: continued pretraining of an existing open model, a RAG index, an eval set — your tools, your stack, with EXPORT.json carrying the pedigree into your compliance story.

Auditable AI for regulated work

Finance, healthcare, government: the auditor gets a signed, hash-pinned record of the training input. License partitioning and takedown are built into the format.

Sovereign & public AI

A model whose entire training input is inspectable, license-clean, and rebuildable inside your own borders. Where it was trained stops mattering, because what it was trained on is on the record.

Reproducible research

A published model anyone can replay: same index commit, same data, same recipe, same architecture. Ablations and dataset studies become diffs against a pinned tree instead of archaeology.

And the loop closes the open-source way: what you can openly license, you contribute back — and every model built on the foundation afterward knows it.
